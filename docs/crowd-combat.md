# 군중 전투 정체 개선 — 2026-11-19

## 확인한 원인과 적용

- 기존 공격 슬롯을 가진 접근자가 먼저 예약해, 이미 타격 거리 안에 있는 유닛까지 대기할 수 있었다. **현재 위치에서 실제 공격 가능한 유닛을 먼저 배정**하고 남은 용량으로 접근자를 배정한다. 이미 교전 중인 유닛은 유지하며 대상별 3명 제한은 그대로 둔다.
- 계획 후 다른 유닛이 이동선을 막으면 이동이 거절되었다. **8방향의 짧은 회피 후보**를 검사해 장애물 옆으로 움직인다. 선택한 회피 지점은 도착하거나 막힐 때까지 유지해 매 틱 방향을 바꾸지 않게 한다.
- 정적 지형은 통과 가능하지만 유닛 때문에 전체 접근 경로를 찾지 못하면, 짧은 안전 구간부터 진행하고 다음 계획에서 재평가한다. 기존 직선·외곽 우회 계획을 우선한다.
- 타깃 거리 동점은 `SpawnOrder`로 결정한다. 전투 이동·공격은 고정 틱 안에서만 진행하고 외부 패키지나 물리는 사용하지 않는다.
- 벽 시야 차단, 이동 충돌, 공격선의 다른 유닛 차단, 원래 경로로 복귀할 수 있는 범위를 유지한다. 슬롯이 모두 찼거나 실제 공간이 없으면 대기는 여전히 필요하다. 복잡한 군집 교착을 모두 푸는 전역 탐색은 아니다.

## 조사한 기법

- [Game AI Pro — Beyond the Kung-Fu Circle, Michael Dawe](https://www.gameaipro.com/GameAIPro/GameAIPro_Chapter28_Beyond_the_Kung-Fu_Circle_A_Flexible_System_for_Managing_NPC_Attacks.pdf): 중앙 공격 슬롯 관리와 현재 공격하기 좋은 유닛으로 슬롯 재배정(28.6.1)을 참고했다. 플레이어 한 명을 보호하기 위한 공격 토큰/공격 후 강제 교대는 이번 팩션 간 전투에 추가하지 않았다.
- [Craig Reynolds — Steering Behaviors](https://www.red3d.com/cwr/steer/): 목표 이동과 주변 장애물 회피를 구분하는 방식을 참고해, 기존 배치 계획 아래에 결정론적 근거리 회피를 추가했다.
- [UNC — ORCA](https://gamma.cs.unc.edu/ORCA/), [A* Pathfinding Project — Local Avoidance](https://arongranberg.com/astar/documentation/stable/localavoidance.html): 상호 속도 회피와 지역 회피의 한계를 조사했다. 이번 구현은 ORCA/RVO 구현이 아니라 소규모 후보 방향 탐색이다. 공격 자리 예약 문제도 함께 있어 엔진/이동 시스템 전체 교체는 하지 않았다.

## 검증 결과

기존 코드에서 신규 회귀 테스트 4개 중 **자리 선점과 동적 장애물 회피 2개 실패**를 확인했다. 수정 후 추가 검사까지 포함해 **Unity 6000.3.28f1 EditMode 15/15 통과**. 프레임 속도별 틱 상태 일치·명령 리플레이·전투/화면 분리 검사도 포함한다.

실제 GameScene Play Mode는 1라운드 1,595틱, 코어 118, 남은 적 0으로 종료했다. 원본 프로젝트가 에디터에서 열려 있어 검증용 복사본에서 수행했다. 복사본 시작 시 Unity Search 인덱서 예외가 있었으나 관련 C# 컴파일 오류 없이 테스트/Play Mode는 완료했다. Windows 빌드와 사용자가 본 개별 장면의 육안 비교는 수행하지 않았다.

## 후속 조정: 유닛 점유 간격 확대

화면상 몸체가 밀집하는 문제를 줄이기 위해 공통 중심 간격 `DefenseBattle.UnitSpacing`을 **0.44 → 1.2칸**으로 확대했다. 이는 유닛 사이에 두는 공통 여유 공간이며, 모델 크기나 벽용 이동 판정은 바꾸지 않는다. 이동·회피·대기·공격 자리 예약·스폰 대기가 같은 간격을 사용한다. 공격 대상이라는 이유로 이동 충돌 간격을 줄이던 예외도 제거했다.

새 수치에서 9/20/40마리씩의 여섯 전투 모두 종료했고 최소 간격 1.2를 유지했다. 실제 GameScene Play Mode에서도 최소 1.20000, 코어 116, 생존 적 0으로 라운드를 마쳤으며 확대 화면을 확인했다. 이 수치는 첫 플레이 조정값이고, 위 표의 0.44 간격 비교 결과와 구분해야 한다. 좁은 길에서는 스폰과 후속 유닛 진입이 늦어져 전투 시간과 결과가 달라진다.

기존 정체 재현용 작은 좌표 배치는 간격 0.44를 고정해 회귀 조건을 보존하고, 밀집 전투 테스트는 실제 게임 간격 1.2를 사용한다. 짧은 공격 사거리도 상대 점유 영역 침범을 허용하지 않는 검사를 추가했다. 자료는 [간격 확대 검증](../ai-use/evidence/20261119-unit-spacing/)에 있다. 확인 화면은 현재 첫 라운드이며, 모든 대형 모델의 날개·무기 애니메이션까지 메시 단위로 비관통을 보장하는 판정은 아니다.

## 현재 설정: 몸통 크기별 점유 반경

공통 1.2칸은 사용하지 않는다. `EnemyCatalog` 각 유닛의 **몸통 반경 × 모델 배율**을 `EnemyFaction.BodyRadius`로 전달하고, 이동·스폰·공격 자리 예약에는 **두 실제 반경 합 + 0.06칸**을 적용한다. 공격선은 가로막는 유닛의 실제 반경으로 확인한다. 반경은 몸통 기준으로 설정한 초기 조정값이며 무기·날개 전체 바운드에서 자동 추출한 값은 아니다. 모델·렌더러를 전투 루프에서 읽지 않는다.

| 조합 | 현재 중심 최소 간격 |
| --- | --- |
| 고블린 전사(1500)–좀비 | 0.34 + 0.312 + 0.06 = 0.712칸 |
| 좀비–좀비 | 0.684칸 |
| 오크–늑대인간 | 0.4 + 0.476 + 0.06 = 0.936칸 |
| 와이번–와이번 | 1.06칸 |

Inspector의 유닛 항목을 펼치면 **몸통 반경**, **모델 배율**, **실제 점유 반경**을 확인할 수 있다. 근거리 회피 길이는 몸통 크기를 따르되 0.4~0.9칸으로 제한한다. 큰 유닛이 인접 스폰에서 같은 틱에 나오더라도 먼저 나온 유닛과의 간격을 다시 검사한다.

### 적을 더 적극적으로 찾게 할 때 조정할 값

- **Enemy Catalog → 인지 (`awarenessRange`)**: 적을 발견하고 추격할 최대 거리. 현재 근접 2.2, 일부 유닛 2.5, 원거리 3.5칸이다. 근접 유닛은 3.0부터 시험하고, 더 넓은 합류가 필요하면 3.5로 비교한다. 벽에 가린 적은 이 값을 키워도 발견하지 못한다. 이번 작업에서는 인지 수치를 바꾸지 않았다.
- **`CombatPositioning.MaxAttackersPerTarget = 3`**: 한 적에게 접근·공격 자리를 배정할 최대 인원. 이미 적을 찾았지만 자리가 차서 대기한다면 이 제한과 주변 공간을 확인한다. 4로 늘리면 집중 공격과 전투 밸런스가 바뀌므로 인지 거리와 별도로 비교해야 한다.
- **`DefenseBattle.CombatPlanInterval = 0.12초`**: 타깃·공격 자리를 다시 계획하는 주기. 찾을 수 있는 거리 자체를 늘리지는 않으며, 현재는 반응 지연보다 거리·슬롯·공간을 먼저 조정한다.
- **공격 사거리 (`attackRange`)**: 발견한 적을 실제로 때릴 수 있는 거리. 탐색 목적의 첫 조정값은 인지 거리다. 현재 모든 카탈로그 유닛 조합은 공격 가능한 간격 안에 점유 반경이 들어간다.

혼합 크기 유닛의 간격, 인접 스폰, 인지 거리 경계, 고정 틱 결정론을 검사했다. [현재 검증 자료](../ai-use/evidence/20261119-body-radii/)와 `Assets/09_Tests/Editor/CombatPositioningTests.cs` 참고. `BalanceSim`도 반경과 모델 배율을 읽도록 맞췄으며, 함께 발견된 이전 생성자·카탈로그 형식·그리드 생성 참조를 현재 API에 맞췄다.

## 정체 시 타깃 재선정

인지 거리와 별도로 **접근 진전**을 검사한다. 매 고정 틱에 계획한 공격 자리까지 남은 거리(현재 웨이포인트까지 + 이후 경로 길이)가 최소 0.05칸 줄었는지 본다. 실제 이동량만 보지 않으므로 옆으로 맴도는 것도 정체로 잡는다. 슬롯이나 계획을 다시 계산하는 것만으로 정체 시간이 초기화되지 않는다.

- `CombatPositioning.StalledRetargetDelay = 0.6초`: 진전이 없으면 다음 전투 계획에서 기존 대상의 자리를 다시 예약하기 전에 다른 적을 찾는다. 계획 주기 0.12초는 고정 틱에서 약 0.133초이므로 판정 직후 바로 전환하지 않을 수 있다.
- `ApproachProgressThreshold = 0.05칸`: 접근 진전으로 인정할 최소 감소량. 단순히 대기 시간을 짧게 만드는 것보다 맴돎을 구분하기 위한 값이다.
- 재선정 후보는 살아 있는 다른 팩션, 인지 거리 안, 벽 시야 확보, 공격자 수 제한과 몸통 간격을 만족해야 한다. **공격 자리까지 완전한 직선/우회 경로가 있는 적** 가운데 경로 길이가 짧은 적을 고른다. 동점은 `SpawnOrder`다. 짧은 회피 한 걸음만 가능한 적을 접근 성공으로 취급해 바꾸지는 않는다.
- 새 대상으로 바꾸면 진행 기준을 새로 잡고 정상적으로 접근/공격하는 동안 유지한다. 공격 쿨다운, 정상 우회 진행, 이동 일시정지는 정체 전환을 유발하지 않는다. 대안이 없으면 기존 접근을 계속 시도하고 약 0.6초 뒤 다시 검사한다. 공간이 비면 기존 적에게 접근할 수 있다.
- 기존 대상에게 아예 자리를 배정하지 못할 때도 완전한 접근 경로가 있는 대안을 먼저 고르고, 없을 때 근거리 회피를 시도한다. 인지 거리·몸통 반경·대상당 3명 제한은 이번에 변경하지 않았다.

재현 사례는 **이전 6초간 맴돎·공격 불가 → 이후 0.8초에 전환·1.3초에 공격 가능**으로 바뀌었다. Unity EditMode 30/30(기존 22 + 신규 8), 고정 틱 결정론·리플레이·비관통 검사 통과. 실제 GameScene Play Mode도 코어 118, 생존 적 0으로 종료했다. [코드·결과·한계](../ai-use/evidence/20261119-stalled-retarget/README.md)를 참고한다. 타깃 선택과 교전 순서가 바뀌므로 전투 밸런스는 플레이 테스트에서 다시 확인한다.

## 직접 플레이 후속 수정: 타깃 없는 후열의 왕복

`GameScene_LeftCoreHud` 첫 웨이브를 직접 재생해 확인했다. 후열의 반복 회전은 타깃을 바꾸는 상황만의 문제가 아니었다. **타깃이 없는 유닛이 막힌 줄 옆으로 비켰다가, 앞쪽 재합류에 실패하면 원래 위치로 돌아오는 동작**을 반복했다. 이런 유닛에는 정체 타깃 재선정이 적용되지 않는다.

`TryFindRouteYield`는 이제 옆 지점과 앞쪽 웨이포인트까지 두 구간을 확인한다. 앞쪽 3개 지점 안에서 실제 합류 가능한 우회만 선택하며, `RouteBypassOffset`으로 정한 합류 지점을 도착까지 유지한다. 몸통 간격 1배/2배의 회피 후보를 검사한다. 경로가 없으면 위치와 방향을 유지해 대기하고, 길이 열리면 전진한다. 막힌 이동 요청만으로 방향을 갱신하지 않는다.

같은 씬 Play Mode 전후 계측에서 문제 후열 해골(SpawnOrder 7)의 **타깃 없는 100도 초과 방향 전환 12회 → 0회**, 공격 횟수 3회 → 7회를 확인했다. 첫 웨이브 전체 큰 경로 방향 전환은 29회 → 1회(정상 복귀 전환도 포함)다. 코어 118·생존 적 0으로 끝났으며 최소 몸통 간격을 유지했다. 실제 장면을 고정한 회귀 검사와 좁은 길/빈 옆길/합류 지점 유지 검사까지 **Unity EditMode 34/34 통과**. [전후 화면·틱 기록·검증 범위](../ai-use/evidence/20261119-rear-route-loop/README.md)를 참고한다.

## 현재 후열 행동: 주변 교전으로 합류

직전의 안정 대기만으로는 앞의 결투를 줄지어 기다리는 문제가 남았다. `CombatJoinRange = 4.5칸`을 추가해, **실제로 교전 중인 유닛이 보이면 후열도 주변 적의 빈 공격 자리로 합류**하도록 했다. 일반 인지 거리와 별도이며 합류 중인 기존 타깃도 이 범위에서 유지한다. 단순 발견으로 인지가 무한 전파되지 않고 실제 공격 가능한 교전 스냅샷을 사용한다. 벽·몸통 간격·대상당 3명 제한은 유지한다.

기존 슬롯/우회/정체 재선정을 사용해 옆 공간으로 퍼진다. 교전 뒤에는 보이는 앞쪽 경로에 복귀하며 과거의 경로 지점이 벽에 가려졌다는 이유만으로 막히지 않는다. 코어 경계는 장거리 합류 목표에서 제외하고, 마지막 바닥 칸에서 정상 경로 이동으로 진입한다. 문 주변 우회에는 몸통 간격 1/8~2배의 후보를 써 작은 조정도 허용한다.

같은 `GameScene_LeftCoreHud` 첫 웨이브의 실제 Play Mode 기록에서 **첫 교전 후 5초 안에 공격한 유닛 3명 → 8명**, 최종 동시 공격 가능 최대 6명을 확인했다. 전원 첫 공격까지는 15.8초 → 6.15초(첫 교전 기준). **40/40 EditMode 통과**, 코어 115·생존 0으로 종료하고 간격을 지켰다. 코어 결과는 직전 118과 달라져 밸런스 재확인이 필요하다.
