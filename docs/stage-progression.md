# 스테이지 진행 저장

2026-11-19. 새 기록은 해안가만 열린 상태로 시작한다. 승리하면 해당 스테이지의 클리어를 저장하고 다음 스테이지를 연다. 마지막 왕도의 승리도 저장한다. 다시 도전하거나 패배했다고 클리어 처리하지 않는다.

승리 결과의 **스테이지 선택** 버튼으로 선택 화면에 돌아갈 수 있다. 실제로 승리한 카드만 `클리어`로 표시한다. 아직 클리어하지 않은 열린 맵 중 첫 번째는 `현재 스테이지`, 나머지는 `입장 가능`, 닫힌 맵은 `잠김`이다. 버튼뿐 아니라 StageSelectionController도 잠긴 맵 진입을 차단한다.

## 진행 관리

스테이지 선택 화면 오른쪽 위의 **진행 관리**에서 두 기능을 제공한다. 메뉴와 확인창은 UIManager 팝업 스택을 사용하며, 취소/Esc는 저장을 변경하지 않는다. 확인창의 초기 키보드 선택은 취소다.

| 기능 | 스테이지 입장 | 클리어 기록 | 스킬 |
| --- | --- | --- | --- |
| 진행 초기화 | 해안가만 열림 | 전부 초기화 | 공격력·힐만 사용 가능 |
| 전체 스테이지 해금 | 다섯 맵 모두 열림 | 기존 실제 기록 유지 | 기존 클리어 조건 유지 |

확인한 변경은 즉시 PlayerPrefs.Save로 저장한다. 전체 해금은 앱 재실행 후에도 유지되며 초기화로 해제할 수 있다. 초기화는 진행 관련 키만 변경하고 오디오 등 다른 설정에는 손대지 않는다. 모든 맵 해금과 모든 스킬 해금은 서로 다른 기능이며 이번 요청에서는 스킬 전체 해금 치트를 추가하지 않았다.

이동속도·방어막·도발은 각각 2·3·4번 클리어에서 열린다. StageSpellUnlocks가 StageProgress의 실제 클리어 기록을 읽으므로 카드의 클리어 상태와 같은 데이터를 사용한다.

## 저장과 기존 기록

- `BeViolenceDefense.Progress.ClearedStages`: 실제 클리어 비트, 1번부터 bit 0 사용.
- `BeViolenceDefense.Progress.AllStagesUnlocked`: 전체 맵 입장 해제 여부.
- 구 버전 `BeViolenceDefense.Progress.SpellStagesCleared`는 새 클리어 키가 없을 때 한 번 가져온다. 구 버전이 기록했던 2·3·4번 승리만 보존하고, 기록하지 않았던 1·5번을 추정해 클리어로 표시하지 않는다. 과거 후반 맵 클리어가 있으면 그 다음 맵까지 입장은 열어 둔다.
- 초기화는 구 키도 삭제하고 새 키에 0을 저장해 과거 기록이 재이관되지 않게 한다.
- 초기화/전체 해금 테스트는 별도 저장 접두사를 사용한다. 사용자의 현재 진행을 테스트 목적으로 초기화하지 않는다.

## 임시 웨이브 종료 기준

실제 선택 화면의 해안가(Stage_Coast → Stage1.asset)와 왕도(Stage_Capital → Stage4.asset)는 웨이브 편성이 없고 종료 기준도 0이어서 무한 증원이었다. 정상적인 순차 진행이 막히므로 두 데이터에 `reinforcementWaveLimit=3`을 임시 적용했다. 기존 적 증원 규칙을 유지하며 3웨이브 후 코어가 생존하고 적이 모두 정리되면 승리한다. 최종 난이도·웨이브 수로 확정한 것은 아니다. 나머지 세 맵은 기존 웨이브 편성을 유지한다.
