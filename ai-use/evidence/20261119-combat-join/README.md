# 후열의 교전 합류 — 일렬 대기 수정

## 사용자 장면과 수정

`GameScene_LeftCoreHud` 첫 웨이브(고블린 4, 해골 6, 추가 벽/마법 없음)를 동일하게 재생했다. 직전 버전은 후열의 왕복을 막았지만, 타깃 없는 후열이 기본 인지 범위 밖의 전투에 참가하지 못해 앞의 결투가 끝날 때까지 줄에 남았다.

- `CombatPositioning.CombatJoinRange = 4.5칸`을 별도로 추가했다. 가까이서 실제 공격 가능한 상태의 교전이 벌어지면, 이를 볼 수 있는 후열이 이 범위 안의 적과 빈 공격 자리를 찾는다. 합류 중인 기존 대상도 이 범위에서 유지한다. 일반 인지 거리보다 작은 값으로 줄이지 않는다.
- 아무 적이나 발견했다는 이유로 확장 범위를 무한 전파하지 않는다. 계획 시작 시 실제 교전 스냅샷을 사용한다. 벽 시야·몸통 간격·대상당 3명 제한은 유지한다.
- 기존 공격 자리/외곽 우회·정체 재선정으로 후열을 옆 공간으로 보낸다. 정상적으로 진행 중인 우회는 유지한다.
- 넓게 교전한 생존자는 과거 경로 지점으로 돌아가는 대신 보이는 앞쪽 경로에 합류한다. 옛 지점이 벽 뒤에 있어도 앞 경로와 연결되면 우회를 허용한다.
- 코어 경계 접촉점을 장거리 합류 목표로 쓰지 않고 마지막 바닥 칸까지 복귀한 뒤 정상 코어 진입 처리를 사용한다. 좁은 문에서 미세한 측면 조정도 찾도록 몸통 간격 1/8, 1/4, 1/2, 1, 2배 후보를 검사한다.

## 검사와 한계

Unity 6000.3.28f1 EditMode **40/40 통과**. 기존 정상 우회 유지·정체 재선정·몸통 비관통·벽·9/20/40명 밀집 전투·결정론·리플레이 검사를 유지했다. 새로 실제 첫 웨이브의 다수 합류/측면 분산, 교전 합류의 거리·벽·실제 교전 조건, 문 주변에서 앞쪽 경로로 복귀하는 사례를 검사했다. 최종 실제 Play Mode는 코어 115·생존 0으로 끝나고 최소 간격 여유 0.00044칸을 지켰다.

중간 검사에서 밀집 전투 종료 실패와 정상 우회 타깃 변경을 발견했다. 이동 중인 정상 우회 유지 규칙을 보존하고, 앞쪽 경로 연결 및 코어 접촉점 처리를 수정한 뒤 전체 검사를 통과했다. 최초 확장 범위 실험의 Play Mode도 복귀 중 멈췄으며 최종 버전에서 해소됐다. 최종 전투 소스/테스트와 검사 복사본의 내용 일치를 확인했다.

원본 에디터와 충돌하지 않도록 `/tmp/be-flank-validation` 복사본을 사용했다. `FlankTickTrace.cs`, `FlankPlayValidation.cs`는 이 복사본에만 있는 계측 코드이며 원본 제품 코드에는 추가하지 않았다. 복사본 Flow의 battle.Tick 직후 `FlankTickTrace.Record(battle, grid)`를 호출했다. 기존 UnityEditor.Search 인덱서 예외는 관찰됐으나 최종 C# 컴파일 오류는 없었다.

일반 인지/공격 사거리와 카탈로그 수치는 이번에 수정하지 않았다. 4.5칸 합류 값은 플레이 조정용 초기 값이다. 모든 웨이브/맵/유닛 조합과 Windows 빌드는 미확인이다.
