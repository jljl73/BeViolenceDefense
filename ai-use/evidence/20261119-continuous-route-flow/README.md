# 연속 경로 화살표 검증

- `DefenseBoardView`의 동시 축소·색상 페이드/제자리 왕복을 경로 전체의 등간격 이동으로 교체했다.
- 이동 속도 0.55칸/초, 간격 0.8칸. 준비 단계 실시간/전투 BattleClock 델타 전달은 기존 호출을 유지한다.
- `RouteFlowPath`는 최대0.28칸 코너 반경의 2차 곡선을 거리표로 샘플링한다. 곡선에서도 이동 속도를 유지하고 접선으로 회전한다.
- 공유 경로는 같은 측면 축으로 차선을 배치하고 폭을 보간한다. 스폰 패드와 코어 끝부분에만 축소 전환을 적용한다.
- Unity6000.3.28f1, 원본 프로젝트를 복제한 `/tmp/be-continuous-routes-validation`에서 실행했다.

## 확인 결과

- EditMode `RouteFlowPathTests` 4/4 통과: 코너 끝점/보행 셀 범위, 등속/방향 연속성, 합류 폭 변화, 중복/빈 경로.
- 실제 `GameScene.unity` Play Mode에서 화면 갱신을 직접 1/15초씩91프레임 진행. 4개 경로의 최소 표시 화살표147개, 내부 화살표의 프레임 간 단절/점프 없음. 델타0 정지, 전체 숨김, 전투 경로 재표시 검사 통과.
- `corner-flow.gif`: 실제 씬의 코너 확대 연속44프레임(약2.93초). GIF 루프 길이는 런타임 반복 주기와 근소하게 다르다.
- `overview.png`, `battle-routes.png`: 실제 씬 전체 준비/전투용 경로 색상.
- 에디터 시작 시 Unity SearchDatabase 색인 예외1건이 관찰됐다. 경로 코드 스택이 아니며 검증은 완료됐다. 새 전투 로직 변경은 없다.

Play Mode 검증은 재현 가능한 화면 갱신을 위해 준비 단계의 VoxelDefensePrototype 자동 업데이트를 끄고 뷰를 직접 갱신했다. 적 전투 결과와 전체 전투 회귀 테스트는 이번 화면 변경의 검증 범위가 아니다.
