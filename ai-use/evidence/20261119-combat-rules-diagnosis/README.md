# 타깃·이동 규칙 진단 증거

전투 코드를 고치지 않고, 유닛이 시간을 어떤 상태로 보내는지와 어색한 사건을 세었다.

## 조건

- 전투 코드: 2026-11-19 07:30경 작업 트리(커밋 `efbd3e0` + 다른 작업의 스테이징된 변경). 파일 해시는 snapshot-hashes.txt. 스냅숏 사본을 떠서 그 사본으로만 실행했다.
- Unity 밖 빌드(net10.0, `BalanceSim/UnityStubs.cs`). Unity와 부동소수 결과가 다를 수 있다. Unity에서는 돌리지 않았다.
- 전투: Stage1·Stage2·설원·묘지 × 벽 배치 4~5종 × 편성 6종 = 114개, 마법 없음. 칸 크기 1(커밋 기준)과 2(진행 중인 맵 배율 변경의 기본값)로 각각 실행.
- 지표는 대리 지표다. 화면에서 직접 본 것이 아니다.

## 파일

| 파일 | 내용 |
| --- | --- |
| summary.txt | 집계 결과와 실험판 비교표 |
| raw-base.tsv | 기준 코드, 전투별 원자료(칸 크기 1·2). 열 이름은 agg.py의 `cols` |
| raw-cap6.tsv, raw-over.tsv, raw-both.tsv, raw-sight.tsv | 규칙을 하나씩 바꾼 실험판(칸 크기 1). 바꾼 내용은 experiment-patches.diff. `both`는 cap6 + over |
| Diag.cs, Diag.csproj | 계측 도구. 유닛·틱마다 상태를 분류한다 |
| run.py, agg.py, compare.py | 실행·집계·비교 |

## 상태 분류

- 타격 위치: 타깃이 있고 지금 자리에서 때릴 수 있음(쿨다운 포함).
- 접근 이동 / 타깃 있고 서 있음: 타깃은 있지만 아직 못 때림.
- 자리 없어 대기: 적은 정했지만 공격 자리를 배정받지 못해 제자리에 섬(`CombatQueue`).
- 경로 이동 / 경로에서 막혀 섬: 타깃 없이 코어로 가는 중.
