# 구조 변경 시험 (저장소 밖 사본)

[진단](../README.md)에서 제안한 구조 변경을 전투 코드 스냅숏 사본에 넣어 같은 전투로 비교했다. 게임 코드에는 아무것도 적용하지 않았다.

## 조건

- 기준: 진단과 같은 스냅숏(snapshot-hashes.txt, 2026-11-19 07:30경 작업 트리). 그 뒤 저장소의 `DefenseBattle.cs`는 다른 작업으로 바뀌었다.
- 전투: 스테이지 4종 114개 + 밀집 전투 8개(기본 지형, 진영당 9·20·40·60명, 벽 없음/4개, `CombatPositioningTests`의 밀집 전투와 같은 편성). 제한 400초. 마법 없음. Unity 밖 빌드.
- 실험판은 `variants.py <이름> <옵션...>`으로 만든다. 옵션: `pass`(아군은 이동 중 서로 막지 않음), `sep`(서 있는 채 겹친 아군을 모두 밀어냄), `sep2`(자리를 배정받지 못한 유닛만 비킴), `reroute`(경로 밖에서 타깃이 없으면 항상 현재 위치에서 코어 경로), `overally`(공격선이 아군 몸통에 막히지 않음), `capN`(대상당 N명), `open`(고정 자리를 못 잡으면 누구나 사거리 안 빈 지점 사용), `sight`(시야를 이동 판정과 같게).

## 파일

## 읽을 때 주의

- "위치 이동 방향 전환"은 밀려서 생긴 1/60칸짜리 움직임도 센다. 화면에서 유닛이 돌아서는 횟수는 "바라보는 방향 뒤집힘"이다.
- "인지 중 때릴 수 없던 비율"은 분모(적을 인지한 시간)가 실험판마다 다르다. 유닛이 싸움터에 빨리 닿으면 분모가 커진다.
- 실험판의 밀어내기 규칙은 거칠다. 수치는 방향을 보는 용도다.
