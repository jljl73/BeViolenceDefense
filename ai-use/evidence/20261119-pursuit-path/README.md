# 타깃 유지와 큰 우회 추격 — 2026-11-19

## 현재 규칙

- 새 적 발견은 기존 인지 거리와 벽 시야 검사를 유지한다. 이미 잡은 적은 거리 또는 시야 가림만으로 해제하지 않는다.
- 마지막으로 보인 위치를 별도로 저장한다. 벽에 가린 동안 상대의 실제 이동 위치로 갱신하지 않으며, 바라보는 방향과 추격 목표도 마지막 목격 위치를 사용한다.
- 코어를 제외한 맵의 0.5칸 간격 통행 지점을 A*로 탐색한다. 적의 빈 공격 자리 또는 마지막 목격 위치 주변의 관찰 가능한 자리까지, 처음에는 적 반대 방향으로 가야 하는 경로도 찾는다. 별도의 8~10칸 거리 상한을 두지 않았다.
- 선택한 경로를 보관하고 막히거나 목표 위치가 달라질 때 재계산한다. 실제 이동마다 유닛 반경·간격과 벽을 다시 검사한다. 정체는 남은 경로 길이로 판단한다.
- 길이 막혔을 때 유닛을 제외한 지형만으로도 갈 수 없는지 구분한다. 일시적인 군중 정체는 타깃 포기 사유로 삼지 않고 기존 대체 타깃/대기 규칙을 이용한다. 지형상 불가능하다고 판단한 대상은 위치·지형 조건이 달라지면 다시 검토할 수 있다.
- 타깃 사망, 정적으로 도달할 수 없는 위치, 마지막 목격 위치를 볼 수 있는 곳에 도착한 뒤에도 4초간 재발견하지 못하는 경우는 해제한다. 가까운 적과 즉시 교전하거나 피격에 대응하는 기존 우선순위에 따른 전환도 가능하다.
- 추격 중 타깃이 죽어도 멀리 돌아간 지점에서 코어 경로로 복귀할 수 있도록 같은 경로 탐색을 사용한다. 최초 발견 범위, 몸통 반경, 대상당 공격자 3명 제한은 바꾸지 않았다.

## 검사

Unity 6000.3.28f1 EditMode **58/58 통과**. 고정 틱·프레임 패턴별 동일 결과·리플레이·코드 순수성, 기존 후열 합류·밀집 전투·피격 반응을 포함한다. U자 벽에서 처음에 뒤로 나가 10칸 넘게 돌아서 같은 타깃에 도달, 인지 밖으로 멀어진 적 유지, 가려진 적의 마지막 목격 위치 유지, 실제로 갇힌 적 대신 접근 가능한 적 선택, 추격 중 대상 사망 후 코어 경로 복귀를 검사했다.

이전의 `StalledSidestepsSwitchToReachableNeighborAndStartAttacking`는 주변 유닛 벽을 피해 갈 수 있어도 0.6초 후 다른 적으로 바뀌기를 요구했다. 이번 요청에 맞춰 같은 배치에서 긴 우회를 선택하고 기존 타깃을 실제로 공격하는 검사로 교체했다. 도달 불가능할 때 재선정하는 검사는 별도로 추가했다.

중간 검사에서는 밀집 전투 종료 실패와 마지막 목격 위치 접근 문제가 드러났다. 타깃 중심을 목적지로 삼으면 타깃 자체가 막고 있던 문제를 주변 관찰 자리로 접근하게 수정했다. 코어 복귀 검사의 마지막 실패는 정상적인 코어 진입을 코어 회피 검사로 금지한 검사 조건이어서, 코어에 도달하기 전까지만 벽/코어 관통을 검사하도록 고쳤다. 중간 XML을 함께 보존했다.

## 실행 범위

원본 에디터가 열려 있어 `/tmp/be-pursuit-validation` 복사본에서 Unity CLI를 실행했다. EditMode는 `-batchmode -nographics -runTests -testPlatform EditMode`, 실제 씬은 `-batchmode -executeMethod PursuitPlayValidation.Run`을 사용한다. 진단 스크립트와 틱 기록 호출은 복사본에만 넣었고 원본 씬/Flow에는 넣지 않았다. 전투/검사 파일 6개의 최종 원본과 검증 복사본 바이트 일치를 확인했다.

`pursuit-change.patch`는 이번 작업 직전 스냅샷과의 비교이며, 앞선 인지/피격 변경이나 동시 UI 수정과 구분한다. 결정론 검사의 추가 해시 필드는 현재 소스와 `source-hashes.txt`에 포함된다.

Windows 빌드와 모든 스테이지/편성의 밸런스는 이번 확인 범위가 아니다. 유닛 사이 충돌은 기존 몸통 반경 모델을 사용한다.
