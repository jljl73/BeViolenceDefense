# 후열 유닛의 방향 왕복 — 직접 플레이 관찰과 수정

## 관찰 범위

사용자 에디터의 현재 씬은 `Assets/01_Scenes/03_Test/GameScene_LeftCoreHud.unity`였다. CUA로 실제 에디터에서 플레이·첫 웨이브 시작·교전 지점 확대·7/14/19초 화면 관찰 후 플레이를 종료했다. 첫 실행은 Update/LateUpdate의 null 참조로 중단됐으나 다시 시작한 실행에서는 관찰되지 않았다. 동시 스크립트 변경에 따른 재초기화 누락으로 추정하며 별도 원인 확정은 하지 않았다.

이후 동일 씬을 `/tmp/be-rear-validation`에서 실행하고 매 전투 틱의 위치·방향·타깃·대기·회피 지점을 기록했다. 수정 후에도 같은 씬과 편성(고블린 4, 해골 6), 마법/추가 벽 없음으로 재생했다. 최종 세 전투 소스와 검증 복사본 내용 일치를 확인했다. 화면 애니메이션 코드는 이번 작업에서 수정하지 않았다.

## 확인한 원인

문제 후열은 큰 방향 전환 시 대부분 Target/CombatQueue가 모두 비어 있었다. 따라서 앞선 `StalledRetargetDelay` 기반 타깃 재선정이 적용될 상태가 아니었다. `TryFindRouteYield`는 옆의 짧은 구간만 비어 있으면 이동시켰고, `AdvanceUnit`은 앞쪽 경로에 재합류할 수 없으면 이전 RoutePosition으로 돌아오게 했다. 같은 자리에 다시 막혀 `옆으로 이동 → 복귀 → 같은 회피`가 반복됐다. 이동이 불가능해도 미리 Face(next)를 적용하던 점도 회전을 유발했다.

## 수정

- 우회 지점까지와 그 지점에서 앞쪽 경로까지 두 구간이 모두 통과 가능한 경우에만 회피한다. 기존 8방향에 몸체 간격 1배/2배 거리 후보를 사용한다.
- 앞쪽 3개 웨이포인트 중 연결할 지점을 기억하고, 도착할 때까지 그보다 뒤쪽으로 다시 돌아가지 않는다. 직선으로 앞쪽 경로에 합류할 수 있으면 먼저 사용한다.
- 유효한 우회가 없으면 방향을 유지하고 기다린다. 공간이 비면 전진한다. 실제 이동이 허용된 후 진행 방향을 바꾼다.
- 기존 타깃 재선정, 인지 거리, 몸통 간격과 공격자 제한은 유지했다.

## 검증

`analyze-turns.py`는 연속 틱의 Heading을 비교해 **그 틱에 타깃/대기 타깃이 없고 100도 넘게 방향을 바꾼 횟수**를 집계한다. 모든 회전이 버그라는 뜻은 아니다. 전투 종료 후 경로 복귀 등 정상 전환도 포함한다.

| 지표 | 이전 | 최종 수정 후 |
| --- | --- | --- |
| 후열 해골 SpawnOrder 7의 큰 경로 방향 전환 | 12 | 0 |
| 같은 유닛의 실제 공격 횟수 | 3 | 7 |
| 첫 웨이브 전체 큰 경로 방향 전환 | 29 | 1 |
| 라운드 종료 코어 체력 / 생존 적 | 118 / 0 | 118 / 0 |
| 최소 몸통 간격 여유 | 0.00017 | 0.00006 |

- Unity EditMode **34/34 통과**. 실제 첫 웨이브 왕복, 좁은 길 안정 대기 후 재개, 열린 옆길 우회, 앞쪽 웨이포인트 유지 4개 회귀 검사 추가. 기존 9/20/40명 밀집 전투·결정론·리플레이·로직 순수성 검사 포함.
- 실제 씬 Play Mode 전후 모두 종료. 새 C# 컴파일 오류 없음. 복사본의 UnityEditor.Search 인덱서 예외는 두 실행 모두 발생했으며 검사 완료에는 영향이 없었다.
- [전후 화면](comparison.gif): 실제 카메라 캡처의 7~14초 구간을 0.5초 간격으로 나란히 배치했다. 부드러운 실시간 녹화가 아니라 비교용 스냅샷이다.
- `before-trace.csv.gz`, `after-trace.csv.gz`: 전체 매 틱 기록. 압축을 푼 CSV 경로를 `python3 analyze-turns.py <before.csv> <after.csv>`에 전달하면 재계산할 수 있다. `turn-summary.txt`는 실행 결과다.
- `RearTickTrace.cs`와 `RearPlayValidation.cs`는 검증 복사본에만 넣은 계측 코드다. 복사본 `VoxelDefensePrototype.Update`의 battle.Tick 직후 `RearTickTrace.Record(battle)` 호출을 추가했다. 본 프로젝트에는 계측 코드를 넣지 않았다.

유효한 길·공격 자리가 없는 후열의 정상 대기는 남는다. 모든 웨이브/유닛 조합, Windows 빌드, 다른 사용자 벽 배치 전수 검사는 하지 않았다.
